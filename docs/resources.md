`memory.current`에는 파일 캐시와 커널 메모리 등이 포함됩니다. 파일 캐시와 익명 메모리만 더한 값이 전체와 같지는 않습니다. 여러 Lean 프로세스의 RSS를 단순 합산하면 공유 페이지를 중복 계산하므로, 위 표는 작업 전체의 cgroup 값을 사용했습니다. 시스템 가용 메모리에는 회수 가능한 캐시가 반영되므로 작업 그룹 메모리를 시스템 RAM에서 단순히 뺀 값과도 다릅니다.

104.65 GiB는 **같은 날 04:42 KST에 32개 병렬 작업 그룹을 시작한 뒤 현재까지의 최대치**입니다. 이전 4개 병렬 구간을 포함한 전체 실행 또는 완주 후의 최대치가 아닙니다. 초기의 약 19~25 GiB 관측값도 전체 최대치로 해석하지 않습니다.

220 GiB는 이 장비에서 설정한 메모리 상한이며, 반드시 그만큼을 사용한다거나 그 용량이 최소 사양이라는 뜻은 아닙니다. 후반부 모듈과 최종 검사에 필요한 자원은 다를 수 있습니다. 최근 처리 속도로 계산한 완료 예상 시간도 확정값이 아닙니다.

실행 중 `du -s -B1`으로 측정한 디스크 사용량은 다음과 같습니다.

이 값은 작업이 실행되는 동안 경로별로 순서대로 측정한 스냅샷입니다. 모든 경로가 정확히 같은 순간의 값은 아니며, 반올림한 행의 합은 표시된 합계와 약간 다를 수 있습니다. Lean 도구 체인 설치 폴더(`.elan`)와 위 경로 밖의 파일은 포함하지 않았습니다. `du`가 측정한 디스크 할당량은 소스 파일의 논리적 바이트 합계와 다릅니다.

이 프로젝트에서는 빌드 과정의 `.setup.json` 파일에 큰 import 정보가 반복되어 디스크 사용량이 늘어날 수 있었습니다. 사용 중인 실행기는 **한 묶음의 빌드가 성공한 뒤, 해당 묶음의 정확한 `.setup.json` 경로만 정리**하고 컴파일 결과와 재개 기록을 유지합니다. 소스와 Lean/Mathlib 버전은 변경하지 않습니다.

관련 파일을 모두 보관한다고 가정한 약 840 GB 추산은 실제로 그만큼의 디스크를 사용했다는 측정 결과가 아닙니다. 완주 후 같은 항목의 최종 사용량을 추가할 예정입니다.
