# RH / Dirichlet GRH Lean 코드의 자체 빌드·공리 검사 결과

**2026년 11월 21일 18:25:47 KST, TRX50 장비에서 원본 프로젝트의 175,187개 모듈 빌드와 최종 정리 5개의 공리 검사를 완료했습니다.** 최종 `Main` 빌드와 공리 검사 명령은 모두 종료 코드 0을 반환했고, 각 정리는 `propext`, `Classical.choice`, `Quot.sound`에만 의존했습니다.

이후 같은 빌드 산출물을 con-leche로 검사한 결과는 [후속 독립 커널 검증 보고서](independent-kernel-result-2026-11-21.md)에 별도로 기록했습니다.

이 보고서는 기존 별도 실행기인 `remote-verify.py`로 수행한 결과입니다. 이 저장소의 새 `verify.sh`를 이용해 설치부터 전체 검증까지 완주한 기록은 아닙니다. 요약 수치와 종료 이벤트는 [완료 기록 JSON](../data/resource-completion.json)에 있습니다.

증명과 원본 Lean 코드의 공로는 **Levent Alpöge와 협력자**에게 있습니다. 우리의 기여는 별도 장비에서의 소스 빌드·공리 검사 재현, 실행 자동화, 자원 사용량 측정과 공개입니다.

| `LFunction_ne_zero_of_half_lt_re` | 명시된 예외를 제외한 `Re(s) > 1/2`에서의 Dirichlet L함수 비소멸 | 표준 3개 |

이 프로젝트에서 다루는 일반화는 **Dirichlet L함수에 대한 GRH**입니다. 위 표는 검사 대상의 요약이며, 우리가 별도 challenge를 만들어 원본 명제와 의미가 일치하는지 검사했다는 뜻은 아닙니다.

실행기는 표준 Lake로 모듈을 의존관계 순서대로 빌드했습니다. 마지막에는 다음 두 명령을 실행했고, [Axioms.lean](../checks/Axioms.lean)의 `#print axioms` 출력에서 다섯 정리와 허용 공리 목록을 확인했습니다.

```bash
lake build +Main:olean
lake env lean --tstack=400000 checks/Axioms.lean
```

최종 빌드 로그의 마지막 문장은 `Build completed successfully (183892 jobs).`입니다. Lake의 183,892개 작업은 의존성 등을 포함한 집계로, 원본 소스 모듈 175,187개와 구분합니다. 로그에는 사용하지 않는 tactic, 실행되지 않는 tactic, 폐기 예정 이름 등에 대한 린터 경고가 남아 있습니다. 빌드 성공은 경고가 전혀 없다는 뜻이 아닙니다.

## 이 결과의 범위

이번 실행으로 확인한 것은 **고정한 환경에서 원본 프로젝트 전체가 빌드되고, 최종 정리 5개가 지정한 표준 공리만을 보고했다는 것**입니다.

다음 작업은 이번 실행에서 수행하지 않았습니다.

- Mathlib만 사용하는 별도 challenge와 원본의 정리·정의를 비교하는 검사
- 별도의 커널 구현으로 증명 항을 다시 검사하는 독립 재검증
- 전체 수학적 논증을 사람이 읽어 이해하고 심사하는 작업
- 새 `verify.sh`로 빈 작업 폴더의 설치 단계부터 시작한 전체 완주 측정

빌드·공리 검사·별도 커널 검사·정리 의미 확인의 구분은 [Lean 공식 검증 지침](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)을 참고할 수 있습니다. 다른 검증자의 공개 결과는 관련 배경 자료이며, 이 보고서의 자체 실행 결과에 합산하지 않았습니다.
